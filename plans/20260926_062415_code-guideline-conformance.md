## 1. What the issue is

Earlier today the docs and the folder layout were aligned with the updated guidelines
(`plans/20260926_053230_align-docs-with-guidelines.md`,
`plans/20260926_060817_align-project-structure.md`). Those plans did not fix app code. They
recorded 8 code gaps (G1–G8) in `docs/known_gaps.md`.

A fresh audit of the code was done for this plan. Baseline:

- `flutter analyze`: no issues.
- `dart format`: 0 files changed.
- `flutter test`: 1,896 tests, all pass.

The audit confirmed G1–G8 and found **new** problems that were not recorded before.

### 1.2 Checked and fine

- No `print`; no `BuildContext` in services or repositories; no SQL in screens or widgets.
- No double-quoted imports. All `@key` descriptions exist in `app_en.arb`.
- `android:allowBackup="false"`. Secrets use `flutter_secure_storage`, not plain `SharedPreferences`.
- Screens that use small pure-Dart helpers (for example `tag_name_rules`, `viewer_transform_service`)
  through providers do no I/O. This is allowed and is left alone.
- The 8 Malayalam values equal to English (`ISO`, `GIF`, `RAW`, `SVG`, `English`,
  `{name}, {date}`) are correct on purpose: technical names, and the language picker must show
  each language in its own script.

## 3. How each fix works (short)

1. **Logger (G8).** `AppLogger` with the six levels in §14.1. It uses `dart:developer` `log`.
   `trace`/`debug` do nothing in the prod flavor. `error`/`fatal` take an error and stack trace.
   It logs operation names only — never file paths, names, GPS or other media metadata.
2. **Error boundaries (G7).** In `main()` before `runApp`: `FlutterError.onError` logs;
   `PlatformDispatcher.instance.onError` logs and returns `true`; in release,
   `ErrorWidget.builder` returns `SafeErrorFallback`. No `runZonedGuarded`.
3. **Layer fixes (N3, N4).** Move the work into a service and provider. The widget keeps only
   UI: the switches, the snackbar, and calling the provider. Behavior stays the same. The temp
   file is also deleted after publishing, which the current code does not do.
4. **About screen (G4, G5).** `details` values may be a string or a `{"en","ml","sa"}` map.
   The screen picks the current language and falls back to `en`. The badge text comes from ARB.
5. **Sanskrit (G1–G3).** Translation of ~1,030 strings is large. I will translate carefully,
   using the glossary, and list any word I am unsure of in the change log for **human review**,
   as §8.5.1 requires. The Hindi-marker test runs in `flutter test`.
6. **`http` removal (N2).** Only the version name and build number are needed, and the app already
   has a Kotlin method channel. A tiny channel method replaces the whole package.

After each phase: `flutter gen-l10n`, `dart format .`, `flutter analyze` (must be clean),
`flutter test` (must pass).

## 4. Decisions I need from you

- **D1 — Scope.** Do all four phases (A → B → C → D), or only some? Phase D (Sanskrit) is by far
  the biggest and needs your review of the translation afterwards.
- **D2 — Fonts.** (a) Bundle subset Noto Sans Devanagari + Noto Sans Malayalam (adds about
  200–400 KB, fully predictable), or (b) rely on Android system fonts with a `fontFamilyFallback`
  chain (no size cost; Android 7+ ships both scripts). I recommend **(b)**, checked on a device.
- **D3 — Relative imports in `test/` (N10).** Dart cannot import `test/` files with `package:`.
  Options: (a) keep the `../` imports and note this as an allowed exception in
  `docs/architecture.md`; (b) move the shared fakes into a `test/helpers/` folder and still import
  them relatively. I recommend **(a)** — it is the standard Dart practice.
- **D4 — `package_info_plus` (N2).** Replace with a Kotlin channel method (recommended), or keep it
  and write it down as an accepted exception (its `http` use is web-only and never runs on Android).
