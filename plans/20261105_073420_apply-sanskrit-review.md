# Apply the owner's Sanskrit review (G9)

**Status:** completed

**Date:** 2026-11-05
**Asked for:** the owner reviewed every Sanskrit string in a review sheet and marked corrections.
**Gaps:** G9 (Sanskrit not reviewed), G50 (labels over the length limit).

## 1. The issue

`app_sa.arb` and the `sa` values in `assets/config/app_config.json` were machine-written and
never reviewed (G9, a release blocker). The owner checked all 1,078 strings and corrected 145:
144 ARB strings and the About screen's licence text.

## 2. What the checks found in the corrections

- No placeholder (`{count}`, `{name}`…) and no plural structure was changed.
- No Hindi marker or nukta letter. One hit from a rough check (`actionBackupRestore`) is a false
  alarm: the word ending `…सञ्चिका ` looks like the Hindi `का`.
- Every short label fits 22 letters. Both Sanskrit G50 labels are now short:
  `titleSyncPairingHeading` → `परयन्त्रेऽन्वीक्ष्यताम्`, `titleVaultKeystoreUnavailable` →
  `सुरक्षितकुञ्चिकाभावः`.
- 52 corrections have spaces at the start or end, and one has three spaces in a row inside a
  line. These are cleaned (trimmed per line, runs of spaces made single). Line breaks are kept.
- **One needs a choice:** `errorPdfFailed` holds two options:
  `PDF स्रष्टुं नाशक्यत (or PDF-सृष्टिर्विफला)`. Only one can ship.

## 3. Files to change

## 4. How

A small script reads the sheet, cleans the spaces, and writes each corrected value into the
right key, keeping key order and file format. It stops if a key is missing or a placeholder
differs. Then `flutter gen-l10n`, `dart format`, `flutter analyze` and `flutter test`. The
language tests (parity, Hindi markers, length) and the screen tests in `sa` must pass.

## 7. Found while applying

All other checks pass, but the Hindi-marker gate fails on 8 corrected strings. The words are
not Hindi. The gate in `docs/guidelines/language_packs/sanskrit_malayalam.md` §4.1 matches some
tokens anywhere in the text, not only as whole words, and the pack says they "may not appear
anywhere":

- `क्या` sits inside `अशक्या` / `अशक्यानि` / `अशक्याः` in `errorEditorSaveFailed`,
  `errorConvertFailed`, `errorBackupFailed`, `errorRestoreFailed`, `errorNotesSaveFailed`,
  `bodyPdfSkippedCount` and `bodyCleanerFailures`.
- `रहा` sits inside `सङ्ग्रहान्वेषणम्` in `titleSearchStart`.

The guidelines folder is read-only, so the gate cannot be changed here. Choices:

- **(a) Recommended.** The owner rewords these 8 strings so that the substrings do not appear
  (for example `न शक्यते` or the earlier `न शक्ता` instead of `अशक्या`, and
  `सङ्ग्रहस्य अन्वेषणम्` instead of `सङ्ग्रहान्वेषणम्`). The gate stays as the pack wrote it.
- **(b)** Keep the owner's wording. Add these 8 keys to a named exception list in
  `test/l10n/sanskrit_hindi_marker_test.dart`, record it as an accepted exception in
  `docs/known_gaps.md`, and write a note asking the guideline owner to match `क्या` and `रहा`
  only as whole words. This departs from a MUST in the pack until the pack changes.

**Owner's choice (2026-11-05): (b).** The words are correct Sanskrit; keep them. Extra files:
`test/l10n/sanskrit_hindi_marker_test.dart` (named exception list `sanskritInsideMarker`, plus a
test that fails if an entry is no longer needed) and `docs/known_gaps.md` §3.

## 8. Note for the guideline owner (DOCS_FOLDER_GUIDELINE §1.1)

- **File:** `language_packs/sanskrit_malayalam.md`, §4.1 "Forbidden markers" and its CI pattern.
- **Change:** match `क्या`, `रहा` (and, by the same reasoning, `रही`, `रहे`, `गया`, `गयी`, `करना`,
  `करके`) only between word edges, as the pattern already does for `है`, `था`, `हो` and `और`.
  Keep `नहीं`, `सेटिंग्स`, `कृपया`, `ऐप` and the nukta check as substring matches, because they do
  not occur inside Sanskrit words.
- **Why:** correct Sanskrit sandhi and compounds contain these letter runs inside a word:
  `अशक्या` (अ + शक्या, "not possible") contains `क्या`, and `सङ्ग्रहान्वेषणम्` contains `रहा`. The
  substring rule forces a reviewer to avoid good Sanskrit or keep an exception list.
- **After the change:** remove `sanskritInsideMarker` from this project's test and the accepted
  exception from `docs/known_gaps.md` §3.
