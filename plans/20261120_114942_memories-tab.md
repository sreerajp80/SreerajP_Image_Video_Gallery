# Plan — "Memories" tab (On this day)

**Status:** completed

## 1. What the issue is

The app already has "On this day" memories, but they are easy to miss:

- They sit in a small row at the top of the Timeline (`FlashbackCarousel`), which starts
  **collapsed** on every app start.
- They show only **today's exact date**, at most **5 years** and **12 photos per year**.
- On most days many users have no photo from the exact date, so the row simply does not appear.

The owner wants the feature as its own bottom-bar tab, with a full page per memory, a
"this week" fallback, and the old Timeline row removed so the feature lives in one place.

## 2. What will change (user view)

1. A new 4th bottom-bar tab, **Memories**, placed second: Timeline · **Memories** · Folders · Albums.
   Material 3 allows 3–5 tabs, so 4 is fine.
2. The tab shows one section per past year, newest year first. Each section has a header such as
   "3 years ago · 20 Nov 2023" and **all** photos and videos from that day, in a grid. No
   12-photo or 5-year cap.
3. **Fallback:** when no past year has media on today's date, the tab shows media from
   **±3 days around today** in past years ("This week in past years"), with a short note at the
   top saying so. Then the header shows the date range, e.g. "3 years ago · 17–23 Nov 2023".
4. When even the week has nothing, a friendly empty message with an icon is shown.
5. Tapping a tile opens the normal viewer (`mediaViewerPath`). Long-press does nothing, the same as
   the old row (no batch selection on this tab).
6. The grid uses the same column count as the Timeline (`gridColumnCountProvider`). Pinch is not
   added on this tab (keeps it simple).
7. Pull-to-refresh runs the same incremental scan as the Timeline.
8. The Timeline loses its "On This Day" row. The "Show memories" switch is removed from
   Settings → Appearance.

**One honest limit:** inside the viewer, swiping left/right moves through the **whole timeline**,
not only that year's memories. This is how the viewer already works for search, trash and albums,
because it pages through `timelineItemsProvider`. For an exact-day memory the neighbours are mostly
the same day anyway. Making the viewer page only through a given list is a separate, larger change
and is **not** in this plan.

## 3. Design (layers)

- **Service (`services/timeline/`):** extend `FlashbackService`.
  - New method `buildPage(items, {now})` returns a `MemoriesPage`: first tries the exact day
    (all years, no item cap); if empty, tries a ±3-day window (`windowDays = 3`).
  - Day matching is done on calendar dates (year/month/day only), so time zones and daylight
    saving cannot shift a photo into the wrong day. The window crosses month and year edges
    correctly (e.g. 30 Dec ± 3 days reaches 2 Jan).
  - 29 February: in the exact-day step a 29 Feb photo matches only on 29 Feb. In the week step it
    is included when 29 Feb is inside the window of that year.
  - Items from the current year are never memories (unchanged rule).
  - The old `build()` (used only by the carousel) is removed.
- **Model (`models/`):** new immutable `MemoriesPage` (`range`: `sameDay` / `sameWeek`,
  `memories`: `List<FlashbackMemory>`). `FlashbackMemory` gets `rangeStart` / `rangeEnd` dates
  (equal for same-day) so the header can show a range. Both keep `const`, `copyWith`, `==`.
- **Provider (`providers/timeline_providers.dart`):** `flashbackMemoriesProvider` becomes
  `memoriesPageProvider` (`FutureProvider<MemoriesPage>`), built from `timelineItemsProvider` and
  `timelineNowProvider`. Using the same list as the viewer keeps "tap → viewer finds the item"
  safe. `flashbackExpandedProvider` is removed.
- **Screen (`screens/memories/memories_screen.dart`):** new tab screen. `CustomScrollView` with a
  `SliverAppBar`-style title "Memories", optional fallback note, then for each memory a header and
  a `SliverGrid` of `MediaGridTile`. Loading → spinner; error → existing error pattern with retry.
- **Widget (`widgets/memories/memory_section_header.dart`):** the year header ("3 years ago ·
  date"). Dates are formatted with the `formattingLocale(...)` helper, never `DateFormat(..., 'sa')`.
- **Home shell:** add the tab to the `IndexedStack` and `NavigationBar`. The "returning to Timeline
  → incremental scan" check stays on index 0.

No database, permission, manifest or dependency change.

## 6. How it will be checked

- `flutter gen-l10n`, `dart format .`, `flutter analyze` (zero issues), `flutter test`.
- Service tests: exact day across several years; no cap on items or years; current year excluded;
  week fallback only when the exact day is empty; window across month end and year end; 29 Feb;
  empty input.
- Screen test: same-day sections render; fallback note shows in week mode; empty message shows;
  tile tap pushes the viewer route; works under `en`, `ml`, `sa`.
- Owner checks on a phone (I cannot): open the tab on a real library, tap a memory, rotate the
  phone, switch language.

## 7. Security impact

None. No network, storage, permission, manifest or dependency change. One saved setting
(`showFlashbacks`) is dropped; old saved values are ignored, not read.

## 8. Risks

- Old phone-move / backup files contain `showFlashbacks`. Parsing must ignore it — covered by a test.
- A very large library with many photos on one day: the grid is lazy (`SliverGrid`), and thumbnails
  load per visible tile, so this is fine.
