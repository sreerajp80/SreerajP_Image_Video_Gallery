# Plan — Kotlin 2.4.20, and record Flutter 3.50.1 as the project version

**Status:** completed

## The issue

The owner upgraded the Flutter SDK on the build machine from 3.47.6 to **3.50.1**
(Dart 3.14.0).

Flutter 3.50.1 checks the Kotlin Gradle plugin (KGP) version at build time
(`DependencyVersionChecker.kt` at tag `3.50.1`):

- below 2.4.20 → warning
- below 2.4.10 → build fails

The project uses **KGP 2.4.10**, so every Android build now prints a warning, and
the project sits exactly at the failure floor. 2.4.20 is also the Kotlin version
Flutter 3.50.1 uses in its own new-project template.

Second issue: the project files still say Flutter 3.47.6 everywhere, and CI builds
with 3.47.6. The owner's machine and CI now use different Flutter versions, so CI
may pass while a local build fails (or the other way round).

AGP 9.4.1 and Gradle 9.8.0 stay as they are:
- AGP 9.4.1 is inside the range Flutter 3.50.1 has tested (up to 9.4). AGP 9.5.1
  exists but Flutter 3.50.1 has not been tested with it.
- Gradle 9.8.0 is newer than Flutter's tested 9.5.0, but it builds today, and
  going back gives nothing.

## The fix

### Part A — Kotlin (the requested change)

- `android/settings.gradle.kts`: `org.jetbrains.kotlin.android` `2.4.10` →
  `2.4.20`.
- `docs/architecture.md` (toolchain line) and `docs/known_gaps.md` (G21): Kotlin
  2.4.10 → 2.4.20.

### Part B — Record Flutter 3.50.1 as the project's version

Same Flutter version locally and in CI. The lowest allowed versions in
`pubspec.yaml` (Flutter 3.41.0 / Dart 3.11.0) do **not** change.

- `.github/workflows/ci.yml`: `flutter-version: 3.47.6` → `3.50.1`.
- `CLAUDE.md`, `AGENTS.md`, `README.md`: Flutter 3.47.6 → 3.50.1, Dart 3.13.5 →
  3.14.0.
- `docs/architecture.md` and `docs/known_gaps.md` (G21): Flutter 3.47.6 →
  3.50.1 (same lines as Part A).
- `play_closed_testing/PUBLISHING_GUIDE.md`: the 16 KB page-size note says
  "Flutter 3.47.6" → 3.50.1.

Left as they are on purpose:
- `docs/implementation_progress.md` line 325 and `docs/release_process.md` line
  376 are history records (what was true on that date), not current settings.
- `docs/guidelines/` is the read-only submodule.
- `pubspec.yaml`, `pubspec.lock`, `assets/config/app_config.json` and the
  `*.g.dart` version files already have uncommitted changes from the owner (version
  2.7.3+36 and a `pub get` with the new Flutter). This plan does not touch them.

## Files to change

- `android/settings.gradle.kts`
- `.github/workflows/ci.yml` (Part B)
- `CLAUDE.md`, `AGENTS.md`, `README.md` (Part B)
- `docs/architecture.md`, `docs/known_gaps.md`
- `play_closed_testing/PUBLISHING_GUIDE.md` (Part B)

No new packages. No Dart or Kotlin source changes.

## How to check

The owner runs these (learning-first: Claude gives the commands):

1. `flutter clean` then `flutter pub get`.
2. `flutter analyze` and `flutter test`. Flutter 3.50.1 may have stricter lint
   rules, so new analyzer messages are possible.
3. `flutter build apk --flavor dev --debug`. Expect: no "Kotlin version" warning.
   Gradle downloads KGP 2.4.20 the first time.
4. `android\gradlew --stop`, then check no `GradleDaemon` / `KotlinCompileDaemon`
   is left.

This build also compiles the Kotlin change from the thumbnail fix
(`MediaStoreChannelHandler.kt`), which has not been compiled yet.

## Risks

- KGP 2.4.10 → 2.4.20 is a patch-level step; low risk.
- Part B: if CI on 3.50.1 shows new analyzer issues, they get fixed in a separate
  plan.

## Security impact

None. A build-tool version and documentation only. No permission, network,
storage or dependency change in the app.
