# Change log — "Set as wallpaper" from the viewer

**Plan:** [plans/20261120_121344_set-as-wallpaper.md](../plans/20261120_121344_set-as-wallpaper.md)

## What changed

The photo viewer's ⋮ menu has a new item, **"Set as wallpaper"**. It opens Android's own
wallpaper screen with the photo. If the phone does not support that screen, Android's "Set as"
list opens instead. If neither can open, a short message is shown. The app never writes the
wallpaper itself, so no permission was added.

The item shows only for an ordinary photo or GIF with a MediaStore address
(`content://media/...`) that is not in the trash or the vault.

## Files

**New**
- `lib/core/domain/viewer/wallpaper_rules.dart` — `canSetAsWallpaper(MediaItem)`.
- `lib/services/platform/wallpaper_service.dart` — calls `setAsWallpaper` on the intents channel;
  returns `false` instead of throwing, and logs only the error code.
- `test/core/domain/viewer/wallpaper_rules_test.dart`, `test/services/platform/wallpaper_service_test.dart`,
  `test/widgets/viewer/viewer_app_bar_test.dart`.

**Changed**
- `android/app/src/main/kotlin/in/sreerajp/imgvidgal/tools/IntentChannelHandler.kt` — new
  `setAsWallpaper`: checks the URI is `content://` with authority `media`, tries
  `WallpaperManager.getCropAndSetWallpaperIntent`, falls back to `ACTION_ATTACH_DATA` in a chooser,
  and grants read access to that one URI only.
- `lib/providers/viewer_providers.dart` — `wallpaperServiceProvider`.
- `lib/widgets/viewer/viewer_app_bar.dart` — menu item and optional `onSetAsWallpaper` callback.
- `lib/screens/viewer/media_viewer_screen.dart` — `_setAsWallpaper` and the failure SnackBar.
- `lib/l10n/app_en.arb`, `app_ml.arb`, `app_sa.arb` and the generated localization files — new keys
  `labelSetAsWallpaper`, `titleSetAsChooser`, `errorSetWallpaperFailed`.
- `test/providers/viewer_providers_test.dart` — checks the new provider.
- `docs/security.md` §10 — the one outgoing URI grant and why there is no `SET_WALLPAPER`.

## Small differences from the plan

- RAW and SVG files are also left out, because Android's wallpaper screen cannot decode them.
  Vaulted items are refused by the rule too, not only by being in a different viewer.
- `onSetAsWallpaper` on `ViewerAppBar` is optional, not required. The menu item shows only when it is
  given. Other places that build the app bar did not need to change.
